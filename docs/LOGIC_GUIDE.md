### 2026-07-23 — brand resolution moved to `brands/<name>.json`; neutral defaults; `.env` loaded in `theme.py`
**What:** Aligned the whole repo with `theme.py`'s current resolution order, which had drifted ahead of every doc, comment, and test. (1) `Theme`'s defaults are now a **neutral, unbranded placeholder** (slate accent, `logo_path=""`, "YOUR BRAND" text marks) — CitiView is no longer the built-in default but a brand file, `brands/citiview.json`. (2) Selection is `BRAND_CONFIG=<path>` (exact file, wins) → `ACTIVE_BRAND=<name>` (→ `brands/<name>.json`, `os.path.basename`-sanitized so a name can't escape the dir via `../`) → defaults. The repo-root `brand.json` fallback is **gone**. (3) **Bug fixed:** `ACTIVE_BRAND` set in `.env` was silently ignored — the only `load_dotenv()` lived in `text_generation.py`, which is imported *after* `app.py → compositor.py → theme.py` has already built `THEME` at import time. `load_dotenv()` now runs inside `theme.py` itself, before `THEME` is built. (4) `brands/*.json` is gitignored per-installation config (like `.env`) with a tracked `brands/_example.json.template` listing every overridable field. (5) Docs/comments/tests realigned: README's Branding section, the folder map, `CLAUDE.md`, `compositor.py`'s header comment, `.env.example` (now documents `ACTIVE_BRAND=citiview`).
**Why:** `theme.py` was the source of truth in code but nothing else described what it actually did — the README still told a new operator to drop `brand.json` at the repo root, which does nothing. Two tests encoded the old assumption and were **already failing**. The dotenv ordering bug meant the documented `.env` pattern couldn't have worked even once it was written down.
**Alternatives rejected:** *`load_dotenv()` in `app.py` before `from theme import THEME`* — fixes only the one import path; anything reaching `theme.py` directly (tests, a future module) would still silently see no `.env`. Putting it in `theme.py` makes the fix correct regardless of import order, which is what "theme.py owns brand resolution" has to mean. *Sourcing `.env` in `run.sh`/`Makefile`* — shell-only fix, leaves `pytest`/direct imports broken. *Forcing `ACTIVE_BRAND=citiview` across the test suite* — would mask regressions in the neutral-default path, which is now the path a fresh clone actually takes. *Committing `brands/citiview.json`* — it is client config (contact phone, logo, taglines), same class as `.env`; the template covers onboarding instead. *Editing the 2026-07-09 entry in place* — it was accurate when written; rewriting it would falsify the log.
**Verification:** suite 104 (2 of them failing on the stale defaults) → **108, all passing** — and re-run with `ACTIVE_BRAND=no_such_brand BRAND_CONFIG=/nope.json` exported to prove the conftest scrub makes the result independent of the developer's environment. Test changes preserve each test's intent and only change *which brand is active*: the CitiView-values test now activates `ACTIVE_BRAND=citiview` with byte-identical assertions; the malformed/missing/unknown-field tests keep using `BRAND_CONFIG` (still a live path) with the fixture renamed off `brand.json`; `test_compositor_constants_come_from_theme` now compares against `theme.THEME` (the *active* theme) rather than `Theme()` defaults — it was silently asserting "defaults == active", which only held while CitiView *was* the default. New coverage: neutral-defaults-when-unselected, `BRAND_CONFIG` beats `ACTIVE_BRAND`, unknown `ACTIVE_BRAND` name → defaults, and empty `logo_path` → text fallback. `tests/conftest.py` gained an autouse fixture scrubbing `ACTIVE_BRAND`/`BRAND_CONFIG`, so a developer's shell or `.env` can no longer change what the suite tests.
**Accepted risks:** `compositor.py`'s no-logo fallback is reached via `os.path.exists("") is False` rather than an explicit empty-string branch — behavior verified and now test-locked, but the *intent* still isn't stated at that line (deliberately unchanged: the brief scoped compositor to report-only). `.env` is now read at `theme.py` import, marginally widening what a stray `.env` key can influence at import time.

### 2026-07-09 — turnkey deployability: vendored Tailwind, /health doctor, theme.py seam, run.sh
**What:** Four packaging moves toward "deployable turnkey local tool with optional brandability". (1) Tailwind is now a committed snapshot (`static/tailwind.css`, built with the Tailwind 3.4.17 standalone CLI scanning `app.py`; regen via `make css`) served from a `/static` mount — the CDN `<script>` is gone, so the running tool has zero network dependency. (2) `GET /health` + `print_preflight()` report ffmpeg/node/agent-SDK/token presence; the UI fetches it on load and shows dismissible banners, and startup prints the same — pure inspection, degradation behavior untouched. (3) Brand extraction: `theme.py` exposes a frozen `Theme` dataclass (CitiView defaults) merged with an optional gitignored `brand.json` (or `BRAND_CONFIG` path); `compositor.py` rebinds its historical module-level constant names from `THEME` so all draw calls, `render_post_package`'s signature, and test imports are unchanged; the UI injects brand chrome via `{{TOKEN}}` sentinel `.replace()` (the HTML stays a plain string — f-string would fight the JS braces); `text_generation.py`/`vision_provider.py` pass `BRAND_NAME`/`BRAND_DESCRIPTION` to the bridges via subprocess env with byte-identical CitiView fallbacks when unset. (4) `run.sh` (idempotent, non-privileged — prints install hints, never sudo) + `Makefile` (`setup`/`run`/`test`/`doctor`/`css`).
**Why:** The only gaps between the audited codebase and a turnkey deliverable were the CDN dependency, late (at-export) discovery of missing system deps, multi-step setup, and the hardcoded brand blocking white-label reuse.
**Alternatives rejected:** *Docker* — adds Docker Desktop + image maintenance for a single-operator WSL user, and the interactive `claude setup-token` flow doesn't containerize cleanly; run.sh keeps the contract simple and a Dockerfile can be layered later. *f-string/Jinja templating for the page* — the inline JS is full of `{}`; sentinel tokens are the minimal safe seam. *Per-run/UI theme picker* — one active theme per installation keeps the render path deterministic and the scope small. *Playwright for the frontend* — a heavy dependency for one page; a TestClient smoke asserting load-bearing element ids + no leaked `{{` tokens guards the new templating seam instead.
**Verification:** default-theme output proven byte-identical via a pixel-diff oracle (fixed synthetic 2-photo render through `_compose_slide`/`_build_endcard`, `ImageChops.difference` bbox None on all frames); a `brand.json` override render diffs exactly in the accent/contact regions; suite grew 92 → 104 (theme defaults/override/malformed-fallback, /health monkeypatched both ways, UI smoke); `./run.sh` exercised end-to-end on this machine (bootstrapped the missing agent SDK, all four doctor checks green, `/`, `/health`, `/static/tailwind.css` all 200).
**Accepted risks:** the Tailwind snapshot must be regenerated when classes change in `app.py` (guarded by the `.bg-zinc-950` presence test + documented `make css`); `brand.json` values are trusted local config (single-operator tool — no validation beyond shape/known-fields).

### 2026-07-06 — item management (remove + incremental add), R7 closed — frontend-only
**What:** Added remove/add item management to the working set, entirely client-side (zero backend changes). `removeItem(uid)` — a labeled, confirm-gated control on both upload cards and Review rows — hard-deletes the photo from `fileArray` and `analysis` in one step, revokes its object URL, and re-renders/regates. A **+ Add more photos** button in Step 4 (and any post-Analyze drop into Step 1, which previously created cards that were *silently excluded from export*) routes new files through an incremental analyze: only the new files are posted to `/analyze-sequence/`, their rows are appended to the end of the sequence, and the operator repositions them with the existing arrows. Export now uploads only files whose uid is in the reviewed sequence and gates on that active count — closing spec R7 (upload set and render set can no longer diverge from the UI). A failed incremental analyze leaves the photos staged-but-excluded with an explicit status message and a Retry control.
**Why:** There was no way to remove a mis-dropped photo at all, and adding photos after Analyze produced the R7 silent-exclusion bug. The backend already supported everything needed (`/analyze-sequence/` accepts any file subset; `/generate-post/` 400-validates uid joins and ignores unreferenced uploads), so the frontend working-set model was the lowest-risk surface to change.
**Alternatives rejected:** *soft delete with restore* — there is no persistent store; "soft" would mean a parallel hidden-items array whose only benefit is undo, at the cost of a second state surface that every consumer (gating, export filter, incremental-analyze scan) must remember to exclude. A confirm dialog before a session-scoped hard delete of a re-addable local file is cheaper and safer. *Full re-analysis on add* — would re-derive rows the operator already reordered/relabeled/edited (edits must win, per Step 4's contract), so re-analysis is destructive; incremental append is the only non-destructive option.
**Accepted risks / tradeoffs:** incremental add does NOT recompute cross-set ordering or near-dup detection between old and new photos — the engine orders new arrivals only among themselves and the operator slots them in manually (documented in README/spec). `upload_index` on old analysis rows goes stale after a removal, which is harmless: every post-Analyze consumer joins by uid. Frontend JS still has no automated browser test (verified via `node --check` on the extracted script + a TestClient smoke replaying the exact new payloads: analyze 3 → remove 1 → incremental add 1 → export 3).

### 2026-07-03 — uid-stable text↔image binding, derived per-image copy, previews
**What:** Slides now join uploaded files to sequence entries by a stable client `uid` (browser posts an aligned `upload_uids` list), not by basename. Uploads write to per-upload subdirs so duplicate basenames don't overwrite. `refine_copy` tiers per-image copy LLM → `derive_default_copy` → blank, and `/analyze-sequence/` always attaches it; the shared `_DEFAULT_COPY` constant was deleted. Added per-image thumbnail previews and `_slides_from_sequence` fail-loud 400s (misaligned/duplicate/unknown uid).
**Why:** Every slide reused one hardcoded fallback triple whenever per-image copy was empty ("all empty" rendered as "all identical"); duplicate basenames overwrote each other on disk; typed copy was silently dropped once Analyze ran.
**Alternatives rejected:** basename/`image_ref` join (collides on duplicate filenames); positional index (breaks on reorder); a single shared default copy (the bug itself).
**Accepted risks:** vision-unavailable batches classify all photos `ambiguous_mixed` with identical grounded context, so their derived copy can match — flagged for review; operator edits by hand.

**What:** UI renumbered to a real dependency chain (Add photos → Event details → Analyze & Sequence → Review → Export) with disable-until-ready gating and the Review panel hidden until Analyze. Removed the generic `/generate-copy/` button + route so grounded copy (inside Analyze) is the only copy path. Fixed three confirmed crashers: R1 (corrupt-but-present image is skipped in the compositor, not a 500), R2 (`_slides_from_metadata` validates length/shape → 400, parity with the sequence path), R3 (`output_name` required + `build_output_paths` suffixes `outputs/<base>[-N]/` to avoid clobber). Aligned `CLAUDE.md`/`spec.md` and added a top-level `README.md`.
**Why:** The first actionable control (generic copy) sat above the dropzone yet demanded "drop files first"; two look-alike copy mechanisms confused users; and a parallel review surfaced real 500s + an output-clobber hazard.
**Alternatives rejected:** keeping/relabeling the generic copy button (still two mechanisms); hide-until-valid gating (less discoverable than disable+hint); timestamped output names (less predictable than reject-blank + numeric suffix).
**Accepted risks:** R7 (image referenced by no sequence entry silently excluded) and R9 (Success names an mp4 ffmpeg never wrote) left as documented risks; frontend JS has no automated browser test (verified via served-HTML markers + manual boot).
